## 街霸 6 分流说明

当前方案：**整进程直连**。`Rules/MyDirectRules.list` 中的 `PROCESS-NAME,StreetFighter6.exe` 把 SF6 的全部流量（登录、匹配、大厅、对局、Steam 网络）交给 DIRECT。

历史沿革：

| 日期 | 方案 |
|------|------|
| 2026-08-20 | 新增「域名代理 + 进程直连兜底」：`streetfighter.com` / `capcom.com` / PlayFab 走 PROXY，进程其余直连 |
| 2026-08-22 | 删除域名部分（commit `0be982a`），改为现在的整进程直连 |

说明：

- 依赖进程名匹配（`PROCESS-NAME`），不需要 sniffer / 域名元数据。
- 只影响 SF6 进程本身；其它软件仍按原配置。
- 如需恢复「域名代理 + 进程直连兜底」：在 `Rules/MyProxyRules.list` 加回 `streetfighter.com`、`capcom.com`、`playfabapi.com`、`playfab.com`，并确保 proxy 规则排在 direct 之前（`PROCESS-NAME` 在前会整进程直连，域名规则失效）。
- 不要把动态 Valve IP 写进长期 list。
- `easy_rules.yaml` 的 `path` 已对齐本仓库 `Rules/*.list`；若客户端工作目录不同，需改 path 或改工作目录映射。

## 格式

Clash classical list，一行一条，**通常不写出口组**（出口在引用它的 RULE-SET 上指定）：

```text
DOMAIN-SUFFIX,example.com
PROCESS-NAME,app.exe
IP-CIDR,1.1.1.1/32
```

## 如何挂进配置

### 方式 A：easy_rules 风格

在覆写 YAML 中：

```yaml
rule-providers:
  my_direct:
    type: file
    behavior: classical
    format: text
    path: Rules/MyDirectRules.list   # 按客户端工作目录改
  my_proxy:
    type: file
    behavior: classical
    format: text
    path: Rules/MyProxyRules.list

+rules:
  - RULE-SET,my_proxy,PROXY
  - RULE-SET,my_direct,DIRECT
```

### 方式 B：直接 +rules

规则很少时可不用 provider，把 list 内容展开成：

```yaml
+rules:
  - DOMAIN-SUFFIX,fut.gg,PROXY
  - DOMAIN-SUFFIX,futbin.com,PROXY
  - PROCESS-NAME,StreetFighter6.exe,DIRECT
  - PROCESS-NAME,FC26.exe,DIRECT
```

### 方式 C：远程 list（jsDelivr raw）

list 需要跨机器复用或频繁更新时，把 provider 指到仓库 raw 地址（本仓库 `Rules/antigravity.list` 即此写法）：

```yaml
rule-providers:
  Antigravity:
    type: http
    behavior: classical
    format: text
    url: https://testingcf.jsdelivr.net/gh/Va1en7/override-hub@main/Rules/antigravity.list
    path: ./ruleset/antigravity.list
    interval: 86400

+rules:
  - RULE-SET,Antigravity,💬 AIGC
```

## 维护建议

- 若要做「域名走代理、其余直连」（如 SF6 的历史方案）：域名 PROXY 在前，同进程 `PROCESS-NAME` DIRECT 在后。  
- 同一业务直连与代理不要写反顺序。  
- `easy_rules.yaml` 的 `path` 与 `Rules/` 文件名需保持一致（现已对齐）；改文件名时同步改 path，避免静默找不到规则。
